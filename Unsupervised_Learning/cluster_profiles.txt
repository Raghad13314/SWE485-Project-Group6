## CLUSTER IDENTITIES

Cluster 0  —  Legitimate (clean)
159,765 URLs | 25.7% phishing
HTTPS=1, no redirects. The dominant URL pattern in the
dataset. Standard safe URLs with no redirect behavior.

Cluster 1  —  Phishing (simple)
44,566 URLs | 100% phishing
HTTPS=0, no redirects. The most common phishing pattern.
Detectable by HTTPS absence alone.

Cluster 2  —  Legitimate (single redirect)
19,967 URLs | 37.4% phishing
HTTPS=1, URL redirect only. Safe URLs that use one
redirect (e.g. link shorteners, login flows).

Cluster 3  —  Legitimate (complex redirect)
4,807 URLs | 23.9% phishing
HTTPS=1, both URL and self-redirect. Rare but benign.
Highest false-positive risk due to redirect complexity.

Cluster 4  —  Phishing (aggressive)
4,650 URLs | 100% phishing
HTTPS=0, both URL and self-redirect. Most dangerous
subgroup — uses full redirect chains to obscure destination.

Cluster 5  —  Phishing (redirect only)
2,040 URLs | 100% phishing
HTTPS=0, URL redirect only. Middle-ground attack pattern.

## KEY FINDINGS

1. Primary separator: IsHTTPS
   Every phishing cluster has IsHTTPS=0.
   Every legitimate cluster has IsHTTPS=1.
   HTTPS absence is the strongest structural signal of phishing
   in this dataset.

2. Secondary separator: Redirect behavior
   NoOfURLRedirect and NoOfSelfRedirect subdivide both phishing
   and legitimate groups into distinct behavioral subgroups.

3. Most remaining features (URLLength, TLDLength, NoOfEqualsInURL,
   NoOfQMarkInURL, NoOfAmpersandInURL, NoOfObfuscatedChar) register
   near 0.00 across all clusters and do not contribute meaningful
   discriminating signal to the cluster structure.

4. K-Means recovered domain-relevant groupings purely from lexical
   URL features, without access to class labels during clustering.

## CLUSTER PROFILES (Interpretation)

Unlike K-Means, DBSCAN produces a larger number of smaller clusters,
each capturing localized density patterns in the data.

- Clusters with IsHTTPS = 0 are consistently 100% phishing,
  confirming that the absence of HTTPS is the strongest structural
  signal of phishing behavior.

- Clusters with IsHTTPS = 1 tend to be legitimate-dominated or mixed,
  especially when redirect activity is low.

- Redirect-related features (NoOfURLRedirect, NoOfSelfRedirect)
  further subdivide both phishing and legitimate groups into more
  specific behavioral patterns.

Overall, DBSCAN provides fine-grained segmentation, separating subtle
variations in URL structure that are grouped together in K-Means.

---

## NOISE ANALYSIS

DBSCAN identified a small proportion of noise points (~0.30%), representing
URLs that do not belong to any dense cluster.

These points exhibit higher variability in features such as URL length,
special characters, and redirect behavior, suggesting more complex or
irregular structures. They may correspond to rare or anomalous URL patterns.

---

## KEY FINDINGS

1. DBSCAN produced 12 clusters with a very low noise ratio (0.30%),
   indicating that most URLs fall into identifiable density regions.

2. Primary structure remains consistent with K-Means:
   IsHTTPS and redirect-related features are the dominant drivers
   of cluster formation.

3. DBSCAN identifies multiple pure phishing clusters, each representing
   structurally similar attack patterns.

4. Compared to K-Means, DBSCAN creates more fragmented clusters,
   splitting similar patterns into smaller subgroups due to sensitivity
   to local density differences.

5. DBSCAN was not selected for integration because:
   - Requires subsampling (cannot scale efficiently to full dataset)
   - Does not support predict() for new URLs
   - Cluster count is not fixed and depends on eps and min_samples

The Silhouette Score of 0.7435 is lower than K-Means (0.8639), which
is expected. BIRCH optimises the CF Tree radius in a single pass over
the data rather than iteratively minimising within-cluster distances
as K-Means does. This structural difference explains the gap without
indicating poor clusters.

The Davies-Bouldin Index of 0.2819 is low, confirming compact and
well-separated clusters, consistent with the K-Means result (0.2231).

BCubed Recall of 0.7203 is notably higher than K-Means (0.5966).
BIRCH's dominant Cluster 0 absorbs 76.2% of the dataset compared to
K-Means Cluster 0 at 67.8%, keeping more same-class URLs together
and increasing recall. The tradeoff is reduced granularity in the
legitimate URL subgroups.

All URLs are phishing and use URL redirection without self-redirect.

Cluster 3 — Pure phishing (both redirects)
4,650 URLs | 100.0% phishing | IsHTTPS=0.0 | URLRedirect=1.0 | SelfRedirect=1.0

All URLs are phishing and use both URL and self-redirect. The most

A micro-cluster of 6 URLs with extreme DomainLength and NoOfSubDomain

4,807 URLs | 23.9% phishing | IsHTTPS=1.0 | URLRedirect=1.0 | SelfRedirect=1.0

Mostly legitimate URLs (76.1%) that use both URL and self-redirect
for functional reasons such as authentication flows and link tracking.
The 23.9% phishing minority represents phishing URLs that deliberately
mimic this redirect pattern while maintaining HTTPS.

## KEY FINDINGS

1. The primary separator across all clusters is IsHTTPS. Every
   cluster with IsHTTPS=0 is 100% phishing. Every cluster with
   IsHTTPS=1 is legitimate-leaning.

2. Redirect behavior (NoOfURLRedirect, NoOfSelfRedirect) acts as the
   secondary separator, subdividing both phishing and legitimate groups
   into four distinct behavioral patterns.

3. Most remaining features register near 0.00 across all clusters and
   do not contribute meaningful discriminating signal to the cluster

4. BIRCH independently converged on the same k=6 and discovered the

5. BIRCH successfully clustered the full 235,795-row dataset in a

SECTION 4: INTEGRATION STRATEGY

SELECTED ALGORITHM: K-Means (k=6)

## RATIONALE

K-Means is selected for integration over DBSCAN and BIRCH for
three practical reasons:

1. Full dataset coverage: K-Means ran on all 235,795 URLs.
   DBSCAN only covered 50,000 rows and cannot assign labels to
   the remaining URLs without refitting.

2. Stable fixed cluster count: K-Means always produces exactly
   k=6 clusters with consistent assignments (same seed), which
   is important when encoding cluster membership as a model feature.

3. Prediction on new URLs: K-Means supports predict() — any new
   URL can be assigned to the nearest centroid at inference time
   without refitting. DBSCAN has no equivalent capability.

## INTEGRATION APPROACH

The K-Means cluster label (0-5) is appended as a new categorical
feature (kmeans_cluster) to the preprocessed dataset and saved
as clustered_data.csv. This file is used to re-train the Phase 1
supervised model with the additional cluster-based signal.

Expected benefit: the cluster label encodes the combination of
IsHTTPS and redirect behavior as a single discrete signal, which
may improve classification of borderline URLs near the decision
boundary where individual features alone are ambiguous.
