3.1 Evaluation Metrics & Visualizations
----------------------------------------------------------------
 
In this section, the performance of the BIRCH model is evaluated
using clustering quality metrics and visualizations. The same
evaluation framework used for K-Means is applied here to allow
direct comparison. Both internal and external metrics are reported.
 
The following metrics are considered:
 
  - Silhouette Score (higher is better): measures how well each
    point fits its own cluster compared to neighboring clusters.
  - Davies-Bouldin Index (lower is better): measures cluster
    compactness and separation.
  - BCubed Precision and Recall: external metrics that compare
    cluster assignments to the true phishing/legitimate labels.
  - WCSS: not reported for BIRCH (see explanation below).
 
 
3.1.1 Internal Evaluation Metrics
----------------------------------
 
  === BIRCH Internal Evaluation Metrics ===
    Silhouette Score      : 0.7435   (5,000-point sample)
    Davies-Bouldin Index  : 0.2819   (10,000-point sample)
 
The Silhouette Score of 0.7435 indicates meaningful cluster cohesion
and separation. It is lower than K-Means (0.8639), which is expected.
BIRCH optimises the CF Tree radius in a single pass over the data
rather than iteratively minimising within-cluster distances as K-Means
does. Each iteration of K-Means moves centroids closer to their
cluster members until convergence; BIRCH has no equivalent refinement
step. This structural difference explains the gap in Silhouette Score
without indicating that BIRCH produced poor clusters — the clusters
themselves represent the same URL behavioral groups.
 
The Davies-Bouldin Index of 0.2819 is low, confirming that the
clusters are compact and well-separated from each other. This is
consistent with the K-Means result (0.2231) and confirms that the
six-cluster structure is internally coherent.
 
Sampling note: Silhouette Score is computed on a 5,000-point random
sample and Davies-Bouldin on a 10,000-point sample because computing
these metrics on the full 235,795-row dataset is computationally
expensive. Sampling is the standard approach for large datasets.
 
Within-Cluster Sum of Squares (WCSS)
--------------------------------------
 
WCSS (Within-Cluster Sum of Squares) is not reported for BIRCH.
The scikit-learn BIRCH implementation does not expose an inertia_
attribute directly, unlike K-Means. WCSS is primarily associated
with centroid-based algorithms that minimise this quantity explicitly
as their objective function. BIRCH minimises CF Tree radius, not WCSS,
so reporting WCSS would not reflect the algorithm's actual optimisation
objective. Silhouette Score and Davies-Bouldin Index are the primary
reliability indicators for BIRCH evaluation.
 
 
3.1.2 BCubed Precision & Recall (External Validation)
-------------------------------------------------------
 
Since ground truth labels are available, BCubed Precision and Recall
are computed to externally validate how well the BIRCH clusters align
with the true phishing/legitimate classes. BCubed evaluates clustering
by checking, for each point, how many points in the same cluster share
the same true label.
 
  - BCubed Precision: of all points in the same cluster, what
    fraction share the same true label?
  - BCubed Recall: of all points with the same true label, what
    fraction are in the same cluster?
  - BCubed F1: harmonic mean of precision and recall.
 
  === BCubed External Validation ===
    BCubed Precision : 0.7076
    BCubed Recall    : 0.7203
    BCubed F1        : 0.7139
 
BCubed Precision of 0.7076 indicates that clusters are reasonably
pure  most points within the same cluster share the same true label.
This is comparable to the K-Means result (0.7096), indicating that
BIRCH achieves similar cluster purity despite its different algorithmic
approach.
 
BCubed Recall of 0.7203 is notably higher than K-Means (0.5966).
This means BIRCH is better at grouping URLs of the same true class
into the same cluster. The reason is that BIRCH's dominant Cluster 0
absorbs a larger proportion of the dataset (76.2%) compared to
K-Means Cluster 0 (67.8%), which keeps more same-class URLs together
and increases recall. The tradeoff is reduced granularity in the
legitimate URL subgroups.
 
BCubed is computed on a 5,000-point sample because its O(n²)
complexity makes it infeasible on 235,795 rows. Silhouette Score
and Davies-Bouldin Index, computed on the full dataset, remain the
primary reliability indicators.

3.3 Key Findings
-------------
 
1. The primary separator across all clusters is IsHTTPS. Every
  cluster with IsHTTPS=0 is 100% phishing. Every cluster with
  IsHTTPS=1 is legitimate-leaning. The absence of HTTPS encryption
  is the single strongest structural signal of phishing in this
  dataset.
 
2. Redirect behavior (NoOfURLRedirect, NoOfSelfRedirect) acts as the
  secondary separator, subdividing both phishing and legitimate groups
  into four distinct behavioral patterns: no redirect, URL redirect
  only, self-redirect only, and both redirects.
 
3. Most remaining features (URLLength, TLDLength, NoOfEqualsInURL,
  NoOfQMarkInURL, NoOfAmpersandInURL, NoOfObfuscatedChar) register
  near 0.00 across all clusters, indicating that they do not
  contribute meaningful discriminating signal to the cluster
  structure.
 
4. BIRCH independently converged on the same k=6 and discovered the
  same six URL behavioral groups as K-Means. Both algorithms
  identified IsHTTPS as the primary separator and redirect behavior
  as the secondary separator. This convergence across two fundamentally
  different algorithmic approaches confirms that this structure is a
  genuine property of the data, not an artifact of either algorithm.
 
5. BIRCH successfully clustered the full 235,795-row dataset in a
  single O(n) pass without requiring subsampling, unlike DBSCAN which
  was limited to 50,000 rows.

SECTION 4: INTEGRATION STRATEGY

SELECTED ALGORITHM: K-Means (k=6)

## RATIONALE

K-Means is selected for integration over DBSCAN and BIRCH for
three practical reasons:

1. Full dataset coverage: K-Means ran on all 235,795 URLs.
   DBSCAN only covered 50,000 rows and cannot assign labels to
   the remaining URLs without refitting.
1. Stable fixed cluster count: K-Means always produces exactly
   k=6 clusters with consistent assignments (same seed), which
   is important when encoding cluster membership as a model feature.
1. Prediction on new URLs: K-Means supports predict() — any new
   URL can be assigned to the nearest centroid at inference time
   without refitting. DBSCAN has no equivalent capability.

## INTEGRATION APPROACH

The K-Means cluster label (0-5) is appended as a new categorical
feature (kmeans_cluster) to the preprocessed dataset and saved
as clustered_data.csv. This file is used to re-train the Phase 1
supervised model with the additional cluster-based signal.

Expected benefit: the cluster label encodes the combination of
IsHTTPS and redirect behavior as a single discrete signal, which
may improve classification of borderline URLs near the decision
boundary where individual features alone are ambiguous.
